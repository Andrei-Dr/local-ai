## Prefill: floor vs measured (Andrei 2026-09-23: "2.1 ms per token is garbage")

Per token the GPU runs all 40 layers: ~3B active params x 2 = ~6 GFLOP of matmul, plus attention against the whole prefix
(10 attention layers x 4 x depth x 4096; ~2 GFLOP at 13k average depth) = ~8 GFLOP. GTX 1650 SUPER: ~19 TOPS int8 dp4a, ~9.6
TFLOPS fp16. Floor at 50% efficiency ~0.8-1.0 ms/token (~1,000 t/s) + expert upload 11 GB/ubatch at 12.4 GB/s (0.22 ms/token
at ub 4096). Measured: ctx1d Pascal build 2.76 ms (362 t/s), served prefill mode 6.0 ms (167 t/s), served ub 128 21 ms (47 t/s).
=> 3-6x above the floor. Suspects, by evidence:
- P1 tensor-core code on a tensor-core-less Turing: MMQ (switch built: GGML_CUDA_MMQ_NO_MMA, mmqdp1) AND FlashAttention prefill
  (fattn-mma-f16 also runs Turing MMA; attention is ~1/3 of the work at 13k) — the Pascal build used the tile kernels there too.
- P2 expert uploads serialized with compute (~0.9 s per ubatch, no overlap) -> copy stream + double buffer (O7).
- P3 per-layer ids readback + sync before the upload; at ub >= 1024 every expert is used -> upload the whole tensor, no readback.
- P4 unmeasured: the -md MTP draft context may re-prefill the whole prompt at ub 128 after the main model.
